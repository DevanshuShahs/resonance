# Resonance - Hybrid Music Recommendation Engine

A music discovery platform that combines local vector search, live ReccoBeats catalog access, and intelligent hybrid ranking. Search millions of tracks via typeahead and get personalized recommendations based on your favorite songs and mood.

## Features

### Live Search
- **Real-time Typeahead** (`GET /tracks/search`) - Access ReccoBeats' full music catalog with instant search results
- **Mood Tag Derivation** - Automatically assign mood labels based on real audio features

### Smart Recommendations
- **Custom Algorithm** (`POST /recommend`) - Our own audio similarity engine with context-aware ranking
- **Hybrid Ranking** - Combines audio similarity (35%), popularity alignment (20%), artist freshness (20%), acoustic profile (15%), and duration alignment (10%)
- **Mood Biasing** - "Happy", "sad", "chill" etc. influence recommendations via audio feature targets
- **Artist Discovery** - Balances between familiar artists and new discoveries

### Local Search (Still Available)
- **Semantic Search**: MiniLM text embeddings + audio features with LSH indexing
- **Full-Text Ranking**: Hand-built BM25 over titles, artists, genres, mood tags
- **Smart SQL Filtering**: Auto-relaxing filters for genre and mood
- **Hybrid Scoring**: 65% semantic + 25% BM25 + 10% popularity

### Frontend
- **Apple Music-Inspired UI** - Dark theme, smooth gradients, glassmorphism effects
- **Live Search Picker** - Find any song instantly
- **Mood Selector** - 12 moods with emoji support
- **Beautiful Result Cards** - Mood tags, popularity, direct Spotify links

## Architecture

### Engine (`engine/`)

Core IR components, framework-agnostic:

- **`vocab.py`**: 14 genres and 12 moods (shared taxonomy for generation and parsing)
- **`config.py`**: Single source of truth for all tunable hyperparameters
- **`text_descriptor.py`**: Builds semantic descriptors from genre + mood tags (title/artist excluded as noise)
- **`audio_norm.py`**: Computes and persists min-max normalization stats for 9 continuous audio features
- **`embeddings.py`**: MiniLM text embeddings + audio feature vectors, unit-normalized and weighted
- **`lsh_index.py`**: Random-hyperplane LSH with multiprobe fallback for efficient ANN
- **`inverted_index.py`**: Hand-built BM25 scoring over terms from all text fields
- **`query_parser.py`**: Rule-based natural-language parser (no LLM) - extracts genres, moods, adjectives
- **`sql_filters.py`**: Converts parsed query into SQL WHERE clauses with automatic relaxation
- **`store.py`**: `EngineStore` class - loads all artifacts once at startup, includes alignment guard
- **`search.py`**: Orchestrates full pipeline - SQL prefilter, LSH/ANN, BM25 scoring, ranking

### API (`api/`)

FastAPI REST interface:

- **`main.py`**: App initialization with lifespan hook to load EngineStore once
- **`routes.py`**: `POST /search` endpoint
- **`schemas.py`**: Pydantic request/response models

### Data & Artifacts

- **`data/tracks.csv`**: Synthetic ~5,000-track catalog (generated by `scripts/generate_dataset.py`)
- **`db/resonance.db`**: SQLite database with tracks and rejected rows (audit log)
- **`artifacts/`**: Persisted embeddings, LSH hyperplanes/buckets, inverted index, normalization stats

### Scripts (`scripts/`)

- **`generate_dataset.py`**: Synthetic track generation with mood-conditioned audio features and intentional defects
- **`load_and_validate.py`**: CSV load, validation, and DB insertion with rejection audit trail
- **`build_embeddings.py`**: Offline build of all artifacts - reads tracks, embeds, builds LSH + BM25
- **`test_search.py`**: Smoke test - 6 canned queries with full score breakdown
- **`bench_ann.py`**: LSH vs brute-force benchmark - latency, candidate count, Jaccard similarity

## Query Parsing & Filtering

The query parser recognizes:

**Genres** (14 types): pop, rock, jazz, hip-hop, country, electronic, indie, classical, folk, metal, reggae, blues, r&b, soul

**Moods** (12 types): happy, sad, energetic, chill, angry, peaceful, melancholic, playful, dreamy, tense, romantic, uplifting

**Audio Adjectives**: upbeat, fast, slow, acoustic, instrumental, danceable, loud, quiet, chill

The parser also supports mood synonyms and translates moods into audio-feature thresholds via `MOOD_AUDIO_HINTS` (e.g., "happy" -> valence > 0.6).

### Relaxation Ladder

If SQL prefilter is too restrictive (yields < 30 results):

1. **Full**: All parsed filters (genre + mood + audio thresholds)
2. **Genre Only**: Drop mood/audio thresholds, keep genre
3. **Unrestricted**: Drop all SQL constraints, pure semantic/BM25

Dropped predicates become score bonuses (+0.05) if candidates happen to satisfy them anyway.

## Scoring

**Final score = 0.65 \* cosine + 0.25 \* bm25_norm + 0.10 \* popularity_norm + relaxation_bonus**

- **Cosine**: Dot-product of query and track embeddings (already unit-normalized)
- **BM25_norm**: Standard BM25 (k1=1.5, b=0.75), normalized to [0,1]
- **Popularity_norm**: Track popularity percentile, normalized to [0,1]
- **Relaxation bonus**: +0.05 per dropped predicate that's satisfied

All candidates are ranked by final score; top-K are returned.

## LSH Performance

**At N=4,876 tracks:**
- LSH candidate retrieval: ~0.02ms
- Brute-force dot-product: ~0.24ms
- **Speedup: 13x** (LSH examines ~7% of dataset)
- Top-10 overlap (Jaccard): 0.39 (expected at this scale; recall vs speed tradeoff)

**Expected scaling:**
- N=50k: LSH ≈1ms vs brute-force ≈2-3ms (10x speedup)
- N=1M: LSH ≈10ms vs brute-force ≈200ms (20x speedup) ← crossover point

At small scales, brute-force is adequate; LSH amortizes the complexity at scale.

## Configuration

All tunable constants in `engine/config.py`:

```python
# Embeddings
TEXT_WEIGHT = 0.6        # weight of text vs audio in combined vector
AUDIO_WEIGHT = 0.4

# LSH (adjust for scale)
LSH_L = 8                # hash tables (raise with L for recall at scale)
LSH_K = 12               # hyperplanes per table (raise with log2(N))
MIN_CANDIDATES = 50      # stop multiprobe once we have this many

# Ranking weights
W_COSINE = 0.65          # semantic similarity
W_BM25 = 0.25            # full-text relevance
W_POPULARITY = 0.10      # popularity signal
RELAXED_PREDICATE_BONUS = 0.05

# SQL filter relaxation
MIN_POOL = 30            # trigger relaxation if prefilter yields < this
```

## Database Schema

**`tracks` table:**
- `id` (PK): unique track identifier
- `title`, `artist`: track metadata
- `genre`: one of 14 supported genres (indexed)
- `mood_tags`: comma-separated mood list
- 9 continuous audio features: danceability, energy, valence, tempo, loudness, speechiness, acousticness, instrumentalness, liveness
- `duration_ms`, `key`, `mode`, `time_signature`, `popularity`
- CHECK constraints on all numeric fields to prevent invalid data

**`rejected_rows` table:**
- `row_num`: original CSV row number
- `errors`: JSON array of validation failures

All validation happens at load time; bad data never reaches the DB.

## Implementation Notes

### What's Included

- ✓ Pretrained sentence-transformer embeddings (MiniLM)
- ✓ Audio feature normalization with persisted min-max stats
- ✓ Random-hyperplane LSH with Hamming-neighbor multiprobe
- ✓ Hand-built BM25 inverted index
- ✓ Rule-based query parser (no LLM)
- ✓ SQL filtering with automatic relaxation ladder
- ✓ Alignment guard on startup (detects DB/embeddings mismatches)
- ✓ FastAPI REST API with lifespan hooks
- ✓ Smoke tests and benchmarks

### Design Decisions

1. **No external ANN libraries** (FAISS, hnswlib, annoy): LSH is simpler to understand, tune, and maintain
2. **Title/artist excluded from embeddings**: Synthetic random names add noise; lexically indexed instead for BM25
3. **Offline artifact build**: No dynamic index construction at API startup - only load/validate once
4. **Alignment guard**: DB and embeddings must stay in sync; fails loudly if they drift
5. **Graceful degradation**: SQL filters relax automatically, never return empty results

### Future Enhancements

- Larger synthetic dataset (50k+) to demonstrate LSH scaling benefits
- User feedback loop (implicit feedback via click-through, explicit via ratings)
- Query reformulation based on low-quality results
- Personalization (user embedding profiles)
- A/B testing framework for tuning weights

## Troubleshooting

**"Alignment check failed"**: DB and embeddings are out of sync. Run `python scripts/build_embeddings.py` after any DB changes.

**"LSH Jaccard < 0.8"**: Expected at small scales. Increase `LSH_K` (e.g., 14 or 16) for better recall, accepting slightly higher query latency.

**"No results from query"**: Query parser didn't recognize genre/mood. The system falls back to pure semantic search, which may still return results. Check `engine/vocab.py` for supported genres/moods.
